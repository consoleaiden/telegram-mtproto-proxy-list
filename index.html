怎么用

点「连接」

Telegram 会弹窗询问是否添加该代理，确认即可。桌面端也可以用旁边的 t.me 链接。

2

确认已启用

设置 → 数据和存储 → 代理，确认「使用代理」已勾选；连不上就换下一个。

3

备几个能用的

公共代理随时会失效。建议收藏 2–3 个本机延迟低的，失效时立刻切换。

常见问题

「访问速率」是怎么测的？

对每条代理发起真实的 MTProto FakeTLS 握手：TCP 建连耗时 + 发出 ClientHello 到收齐服务端 ServerHello / CCS / AppData 的耗时，两者相加即排序用的延迟（毫秒，越小越快）。每台测两次取中位数，避免单次抖动。

「握手校验通过」是什么意思？

服务端返回的摘要等于 HMAC-SHA256(密钥, 客户端随机数 + 服务端握手包)，说明它确实持有该 secret、是真正的 MTProxy，而不是把请求回落到了伪装网站。这类代理的存活率明显更高。

为什么我这里的速度和排行不一致？

排行里的耗时来自测速节点（数据中心网络），「本机检测」是从你自己的网络发起的。出口位置、运营商线路不同，结果差异很正常 —— 自己测出来的才最贴近你的体验。

数据多久更新一次？

每小时一次：重新抓取两个数据源、去重合并、全量测速、重建 proxies.json 与 top40.json。页头会显示本轮数据的时间。

能直接拿 JSON 用吗？

可以。top40.json 是速率最快的前 40 条，字段包含 server、port、secret、link、latency_ms、sources 等；proxies.json 是全量明细；proxies.txt 是仅含存活条目、已按速率排序的明文列表。

数据来源：tgmtproxy（主源） · dubblebyte（次源）。合并、测速与排序由 GitHub Actions 每小时执行一次。
